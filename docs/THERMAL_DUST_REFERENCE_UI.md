# Thermal and dust reference interface

Open **Screening → Thermal & dust** in the current local application. This increment follows the supplied two-panel design using the existing Diviner source context and radiator optical-balance model.

## Delivered

- The reference heading, A/B selection, blurred lunar backdrop, glass observation and radiator panels, study-point selector, historical-data and exploratory-model badges, heatmap axes/legend, source coverage summary, NASA Diviner archive link, clean/dusty radiator illustration, material selector, dust coverage input/slider, device assumptions disclosure, calculated comparison chart, equilibrium/heat-margin readouts and Update sensitivity action.
- The left panel uses only the selected provider's applicable Diviner records. The retained data comprises two 15-minute southern-summer local-time products per catalog point: 00:00–00:15 and 12:00–12:15, accumulated during 2009–2019. Matching source bins are colored at their true widths; absent matches and unloaded local times/seasons remain hatched. Exact values and times are also shown as readable cards below the map. Choosing a new study point uses the existing coverage-checked scenario transaction and preserves the other scenario.
- The heatmap labels the actual named season grouping. It does not invent a solar-longitude season grid, interpolate a daily curve, substitute another point's observations or repeat two temperatures across a dense illustrative matrix. The reported count is matched source products divided by loaded products, not the number of raw measurements. Raw observation counts, temperature error bars and geometry/SNR flags are not present in the prepared bundle and are not fabricated. Reference/sample modes show no borrowed Diviner observations.
- Material presets use the existing pinned laboratory simulant endmembers, with explicit custom optical properties available. All radiator/device assumptions remain editable, including the independent incident flux, view factor, sky/ground temperatures and user comparison limit. Diviner brightness temperatures are never substituted into those inputs.
- The chart uses all 21 points of the existing 0–100% coverage sweep. Its clean-reference line is constant for an unchanged device/illumination, the mixed-optics curve is calculated, the chosen coverage is marked, and the dashed line uses the actual user limit. The mockup's example curve and 260 K limit are not inserted as defaults. Radiator images are illustrative, not equipment data or calibration.
- Initially the curve is a labeled preview and the three readouts remain unevaluated. Update sensitivity enables the existing exploratory assessment for the active scenario and fills clean equilibrium, dusty equilibrium and signed dusty internal-heat margin at the chosen limit. Subsequent valid edits update the evaluated model. The existing enable checkbox controls evaluation/export inclusion. A/B device assumptions remain independent; invalid inputs retain the prior valid state. Keyboard range focus and open disclosures survive recomputation.
- Model/source links, pinned hashes, scope and exclusions remain available. The steady-state, area-weighted optical mixture is not conservative or a calibrated dust-on-coating response; transient behavior and hardware survival remain unassessed. Numerical/scientific code and pinned source bundles are unchanged by this presentation increment.
- Responsive desktop cards and stacked tablet/mobile panels retain every control and disclosure. The backdrop reuses the cached illustrative lunar render; there is no second interactive 3D renderer. The classic interface keeps its existing thermal/dust presentation.

## Validation

The [validation record](review/mission-settings/thermal-validation.json) retains final test results, source hashes, build identities and Chrome/GPU observations. New checks compare every colored cell with the loaded source product, verify missing matches and unsupported modes, compare all three readouts with the actual dust model, test coverage/material/device/limit edits and invalid-input preservation, confirm A/B isolation and unchanged environmental/Diviner results, verify selected-site source switching and date independence, and check bounds from 390 to 3840 pixels.

The broad Chrome run passed 47 of 49 cases. One existing Terrain case had no WebGL canvas and another timed out while sending a keyboard event; both passed in an isolated rerun without an application change. All 49 distinct browser/GPU cases therefore passed across the retained runs. The four final Thermal cases also passed after enlarging mobile SVG labels and separating the legend from axis text. The first Thermal test attempt was corrected to navigate through Explore before using mission settings. Historical-value DOM checks now compare exact source values rather than old rounded text. The retained records distinguish those initial attempts from completed checks.

The final JavaScript/API/DOM run passed 204/204 checks. Production and standalone offline builds passed. The running development page evaluated the default B assumptions as 276.896 K clean, 292.989 K dusty and +382.179 W heat margin, preserving environmental results, historical observations and the other scenario's dust settings. Its browser check reported no JavaScript exceptions. The Windows GPU review observed the AMD hardware renderer with no lost WebGL context. Scientific engine/store, pinned scientific bundles and classic entry hashes match the pre-UI baseline. Full physical scientific/engineering acceptance remains open.
