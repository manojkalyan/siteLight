# Terrain screening reference interface

15 November 2026. Open **Screening → Terrain** in the current local application. This increment implements the supplied “Understand the ground” composition, retaining the existing scientific calculations.

## Delivered

- A selected-scenario heading; responsive 3D terrain viewer and glass evidence panel; editable radius, slope baseline and slope limit; route direction; independent display-layer toggles; source evidence navigation. **Cinematic** is the default presentation requested in the follow-up reference; **Source DEM** switches to measured geometry.
- Cinematic uses a detailed illustrative crater landscape, regolith grain, instanced stones and directional shadows. Source-derived slope cells and the actual sampled route are projected schematically onto it. Their classifications and path nodes remain real calculations, but their registration to the illustrated landforms is not measured. The caption and report export state this explicitly; the cinematic view shows the analysis radius rather than a false physical distance scale. It never supplies heights to the scientific evaluator.
- In Source DEM, the existing NASA PGDA elevation mesh, source-grid convergence rotation and assessed footprint drive the map. Colored square cells are clipped to the selected radius, their corner heights are sampled from the source grid, and colors use the selected slope limit. Known-height cells with unavailable slope are gray; missing-height polygons are omitted instead of inventing heights. The underlying surface, cells, footprint and actual route share the existing meter-to-scene transform.
- Radius/baseline/limit controls recompute the existing footprint statistics. The route uses the existing connectivity evaluator, including diagonal corner and edge-slope checks. Start/end labels and route geometry appear only when a sampled route is found. “No route” remains an explicit evaluated result. Directions remain the source-grid axes rather than implying a Sun-relative planner.
- The source-derived mean slope, detrended roughness, footprint coverage and applicable nominal horizon extent appear above the 100-realization empirical percentile plot. The nominal DEM metrics are separate from ensemble medians. The prepared reference footprint remains labeled with its settings; when settings change it is labeled as differing until the existing current-footprint ensemble action is run. Its result remains keyed to the site and footprint settings and is retained in report exports.
- Stereo comparison details keep their actual coverage; Nobile currently has no matching compared stereo coverage. Source-RMS sensitivity and darkness/Earth-outage intervals retain the existing model qualifications. The far-field warning uses the selected provider's actual extent and conditional height ceiling. Source evidence opens the selected tile's retained source records.
- The same single renderer is moved between Explore, Terrain and Rescue. Source terrain uses explicitly labeled inspection lighting on this screen so geometry can be inspected during darkness; mission illumination and scientific results are unchanged. The north indicator follows the camera; the physical source-grid scale is shown in Source DEM. Cell geometry is batched into at most four fill/outline draw groups, not hundreds of meshes. Existing orbit, zoom, camera reset and reduced-motion behavior remain available. A higher-detail artistic mesh is cached for Screening and its inactive geometry is disposed with the viewer.
- Without WebGL, the assessed source-grid map and calculations remain visible. Reference-only mode displays unassessed terrain instead of another site's metrics. Sample mode retains its explicitly synthetic 2D assessment. Mobile layouts stack the map and evidence, retaining all controls and horizontal subtab navigation.

The measured 5 m DEM remains available through Source DEM. All numerical statistics, cell colors, routes, horizon results and ensemble calculations continue using their existing source data in both presentation modes. Unresolved rocks and hazards, soil/traction, vehicle suitability, physical terrain truth, global covariance and engineering acceptance remain outside this UI increment.

The [validation record](review/mission-settings/terrain-validation.json) retains final test results, builds, protected source hashes and the Windows Chrome/GPU record. The new browser cases compare rendered metrics with the exported real assessment, check route geometry and no-route states, verify slider/layer/direction updates, preserve environmental results and mission dates, check the selected source evidence, test WebGL fallback and unassessed reference mode, and check bounds from 390 to 3840 pixels. Existing ensemble and GPU tests use the new disclosure navigation.

Verification passed 199/199 JavaScript/API/DOM checks and 40/40 cases in the full Chrome/GPU run for the cinematic increment. The final camera framing and sampled-route callout are covered by the four focused Terrain cases, including presentation toggles, preserved mission results, real classifications, keyboard controls, fallback mode and responsive bounds. Both production and standalone offline builds are rebuilt after those refinements. Headed Windows Chrome reported the AMD hardware renderer and no lost WebGL context. Scientific engine/store, prepared scientific bundles and classic entry hashes match the pre-UI baseline; no scientific or engineering acceptance gate is closed by these UI checks.
